## 1. Постановка задачи

**Цель:** сравнить три подхода к прогнозированию временного ряда:
1. **Baseline** — «завтра = сегодня».
2. **MLP** — полносвязная нейросеть.
3. **LSTM** — рекуррентная сеть с памятью.

**Гипотеза (слайд 26):** «LSTM снижает ошибку относительно MLP и baseline на фиксированном TEST».

**Метрики:** MSE (Mean Squared Error), MAE (Mean Absolute Error).

---

## 2. Данные

**Источник:** Yahoo Finance (библиотека `yfinance`).
**Инструмент:** AAPL (Apple Inc.), дневные данные.
**Период:** 2018-01-02 — 2025-12-31 (2011 наблюдений).

**Предобработка (слайд 19, без data leakage):**
- Разбиение на train/test: **80/20** по времени (не перемешиваем).
- Нормализация: `mean` и `std` вычислены **только по train**.
- `scaled = (prices - mean_train) / std_train`.

**Окна (слайд 7):**
- Длина окна `WINDOW = 20` (20 предыдущих дней → 1 следующий).
- Train: 1592 окна.
- Test: 399 окон.

---

## 3. Архитектуры моделей

### MLP (слайд 8)

```
Linear(WINDOW → 64) → ReLU → Linear(64 → 1)
```

- Вход: вектор 20 значений.
- Выход: одно значение (прогноз цены).

### LSTM (слайд 13)

```
LSTM(input_size=1, hidden_size=32, batch_first=True) → Linear(32 → 1)
```

- Вход: последовательность `[batch, 20, 1]`.
- Выход: одно значение.

### Baseline (слайд 5)

```
P[t+1] = P[t]
```

Прогноз = последнее известное значение.

## 4. Параметры эксперимента

**Фиксировано:**
- `WINDOW = 20`
- `EPOCHS = 30`

## 6. Интерпретация

### 6.1. Baseline — сильнейший конкурент

Baseline («завтра = сегодня») даёт **MSE = 0.0056** — это очень низкая ошибка. Причина: **цены акций близки к случайному блужданию**. Сегодняшняя цена — лучший предиктор завтрашней.

Это **ожидаемый результат** для финансовых рядов. Слайд 34 прямо предупреждает:
> «Красивый prediction может просто повторять вчерашнюю цену.»

### 6.2. MLP лучше LSTM на этом датасете

| Модель | Лучший MSE |
|---|---|
| MLP | 0.0070 |
| LSTM | 0.0262 |

**LSTM в 3.7 раза хуже MLP.** Причины:
1. **Мало данных** — 1592 окна недостаточно для LSTM с 32 скрытыми нейронами.
2. **Мало эпох** — 30 эпох недостаточно для рекуррентной сети.
3. **Переобучение** — LSTM склонна запоминать шум на малых данных.

### 6.3. Learning rate критически важен

| lr | MLP MSE | LSTM MSE |
|---|---|---|
| 0.0001 | 0.078 | 0.844 |
| 0.001 | 0.010 | 0.190 |
| **0.01** | **0.007** | **0.026** |

- **При lr=0.0001** — модели **недоучились** за 30 эпох.
- **При lr=0.01** — **лучший результат** для обеих архитектур.

**Вывод:** выбор learning rate даёт **11-кратное улучшение** MSE — важнее, чем выбор архитектуры.

## 7. Ограничения эксперимента

1. **Один инструмент** (AAPL) — результаты не обобщаются на все акции.
2. **Один window** (20) — не проверены другие значения.
3. **30 эпох** — мало для LSTM.
4. **Прогноз цен, а не доходностей** — цены нестационарны, baseline слишком силён.
5. **Не учтены транзакционные издержки** — backtest не проводился.

## 8. Инженерный вывод (слайд 36)

**Плохо:**
> «LSTM показала хорошую точность.»

**Хорошо (наша формулировка):**

> «На фиксированном time split 80/20 ни MLP, ни LSTM **не превзошли baseline** на данных AAPL за 2018–2025. Лучший MLP (lr=0.01) дал MSE=0.0070 против baseline MSE=0.0056 — ухудшение на 25%. LSTM (lr=0.01) дала MSE=0.026 — ухудшение в 4.7 раза. **Это не означает, что модели плохие** — это означает, что **сложность не дала инженерного выигрыша** на задаче, где baseline уже очень сильный. Learning rate критически важен: при lr=0.0001 модели недоучиваются, при lr=0.01 — лучший результат.»

---

## 9. Что можно улучшить (для будущих экспериментов)

1. **Прогнозировать доходности** `r_t = ln(P_t / P_{t-1})` вместо цен — доходности стационарны, baseline будет слабее.
2. **Больше эпох** — 100–200 для LSTM.
3. **Больше данных** — период 2010–2026.
4. **Другие признаки** — Volume, High-Low, RSI, MACD.
5. **Backtest с транзакционными издержками** — проверка прибыльности.
